# 项目总览

## 1. 项目名称

**防逆流设备运行可视化系统**

## 2. 项目背景

公司已有设备数据上报平台。防逆流 CT 电表通过 MQTT 上报数据，平台将数据写入公司数据库。用户能够通过公司数据库地址或平台查询接口获取设备上报记录，但当前缺少一个适合工程、售后和运维人员使用的设备可视化网页。

每台防逆流 CT 电表最多绑定 8 台微型逆变器。CT 电表检测电网电流方向和功率大小，再向微逆下发限流控制，目标是允许微逆发电，但禁止发出的电反送到公共电网。

## 3. 核心业务目标

系统需要回答以下问题：

1. 哪些 CT 设备最近 7 天仍然活跃？
2. 当前设备是否在线？
3. 最近出现过多少次离线，每次离线持续多久？
4. A/B/C 任一相是否出现负功率，即向电网反送？
5. 设备今天发了多少电，累计发了多少电？
6. 家庭负载、电网功率和微逆总功率在最近 7 天如何变化？
7. 绑定的 8 台微逆分别是否在线、是否发电？
8. 每台微逆的 PV1、PV2 和总发电功率是多少？
9. 每台微逆是否存在故障，故障是什么，什么时候出现和恢复？
10. 用户能否通过输入 SN 切换查看不同 CT 设备？

## 4. 当前已验证的产品形态

当前 V4 原型已经验证以下页面结构：

```text
设备总览
└── CT 设备运行面板
    ├── CT 本体运行状态
    ├── 防逆流三相安全状态
    ├── 可缩放功率总览
    ├── 电网电压与频率
    ├── 8 台微逆卡片
    ├── CT 上下线与离线时长
    └── 逆流严重告警记录
        └── 每台微逆详情
            ├── 在线与工作状态
            ├── PV1/PV2/总功率
            ├── 今日与累计发电量
            ├── 内部温度
            ├── 丢包率
            ├── 安装相位与接入点
            └── 故障变化记录
```

## 5. 可借鉴的设计思想

本项目不仅适用于防逆流 CT，也可以复用于其他设备品类。

### 5.1 指标元数据驱动

不同产品上报字段不同，不应把所有字段硬编码在页面。通过指标字典定义：

- 指标名称；
- 单位；
- 数据类型；
- 是否画曲线；
- 图表分组；
- 正常阈值；
- 告警等级；
- 枚举映射；
- 保留周期。

增加新产品时主要增加配置，而不是重新编写整套页面。

### 5.2 最新状态与历史数据分离

- `device_latest` 用于设备总览和快速加载；
- `telemetry` 用于最近 7 天曲线；
- `device_events` 用于上下线和状态变化；
- `fault_events` 用于故障发生、变化和恢复。

这种结构适用于大量设备，并能避免每次从历史表中重新寻找最新值。

### 5.3 设备层级分离

```text
产品品类
└── 产品型号
    └── CT 设备实例
        └── 微逆通道 1～8
```

产品型号、CT 设备 SN、微逆 SN 和微逆通道序号必须分开保存。

### 5.4 原始数据与业务语义分离

公司数据库中的值可能只是状态码、位掩码或原始计量值。系统应通过字典转换为：

- 在线、离线、未配对；
- 待机、发电、断电、限流发电；
- PV1 输入欠压、PV2 输入欠压、PV 电压异常；
- 正常、一般告警、严重逆流告警。

### 5.5 在线系统与离线 HTML 并存

正式 Web 系统用于持续查询和告警；单文件 HTML 继续作为：

- 售后问题快照；
- 阶段验收报告；
- 离线分析；
- 邮件或工单附件；
- 数据迁移前后对比。

## 6. 项目边界

一期、二期默认是只读观察系统，不包含：

- 远程开关机；
- 修改发电限制；
- 反转 CT 方向；
- OTA；
- 配对和解绑；
- 发布 MQTT 控制命令。

这些操作需要单独的权限、审计和安全设计。
