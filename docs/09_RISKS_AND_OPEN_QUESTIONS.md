# 风险与待确认问题

## 1. 公司数据库结构

正式接入前需要确认：

- 数据库类型；
- 表名或视图名；
- 唯一记录 ID；
- 设备 SN 字段；
- SIID；
- PIID；
- 微逆序号；
- 上报时间；
- 平台接收时间；
- 原始值；
- 是否存在删除或更新记录；
- 查询频率限制。

## 2. 发电量单位

当前协议存在：

- 名称是发电量；
- 单位为空或被错误配置成 W；
- 样例数值更像 Wh。

必须由固件或平台负责人确认：

- 今日发电量单位；
- 累计发电量单位；
- 是否需要换算为 kWh；
- 数据是否会每日归零。

## 3. 工作状态归属

当前 Excel 中 `工作状态` 缺少 SIID，无法稳定归属某一台微逆。

正式视图必须包含 SIID 或 inverter_index。

## 4. Inv5/Inv6 字段缺前缀

样例导出中出现：

- `发电功率`
- `pv1功率`
- `pv2功率`

但缺少 Inv5/Inv6 前缀。

正式系统不能依赖时间戳猜测，必须使用 SIID。

## 5. 微逆版本与 SN

当前日志没有：

- 微逆 SN；
- 软件版本；
- 硬件版本；
- Sub1G 版本；
- 所在相；
- 接入点。

需要确认这些属性来自：

- 设备属性表；
- 平台物模型属性接口；
- 配对列表；
- 单独查询 API。

## 6. 在线判定

CT 本体：

- 优先使用平台上线/下线事件；
- 也可用最后上报时间作为保护规则。

微逆：

- 使用 `online_state`；
- 0 未配对；
- 1 离线；
- 2 在线。

需要确认：

- 微逆夜间离线是否为正常；
- 是否要按日出日落或发电窗口降低告警等级；
- 多久不更新状态算数据过期。

## 7. 逆流告警去抖

当前规则是任一负值立即严重告警。

正式系统可能需要确认：

- 是否允许短暂测量抖动；
- 是否需要连续 N 个样本；
- 是否有功率容差，例如小于 -10 W 才告警；
- 三相模式与单相模式规则是否不同。

第一版应保留原始负值，同时将去抖阈值做成配置。

## 8. 数据保留

用户要求最近 7 天。

需要确认：

- 故障历史是否也只保留 7 天；
- 设备元数据是否持续保留；
- 告警汇总是否可以长期保留；
- 是否需要导出归档。

## 9. 权限

需要确认：

- 哪些人可以查看所有设备；
- 是否按客户、项目或地区隔离；
- 是否需要隐藏设备 SN；
- 是否接入公司 SSO。

## 10. 原型与正式系统的差异

当前 HTML 是一次性数据快照。不能直接视为：

- 实时系统；
- 正式告警系统；
- 数据库压力已经验证；
- 安全已经通过；
- 单位完全确认。

Codex 实现时必须保留这些不确定性，不能用猜测填充正式字段。
